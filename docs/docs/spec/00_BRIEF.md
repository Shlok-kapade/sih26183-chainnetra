# 00 — Project Brief

## Problem (SIH26183, Ministry of Home Affairs / I4C)
Victims of cyber fraud report crypto wallet addresses (often burner/intermediary wallets). To freeze funds and preserve evidence, investigators must find **which exchange/VASP received the money**, fast. Manual tracing across chains, swaps, bridges and mixers takes hours; the freeze window is short.

## Product
ChainNetra ingests a victim-reported wallet (single or bulk from complaint feeds), traces fund flow across hops and chains, **attributes the destination** (exchange/VASP, P2P/OTC-suspected, private wallet, mixer, bridge, DEX), scores risk, ranks cases by **freeze urgency**, and generates an evidence-hashed investigation report plus a draft freeze/KYC request.

## Differentiators (what makes this not "BFS + graph + PDF")
1. **ML with measured accuracy** — address-role classifier (LightGBM + optional GNN), calibrated probabilities, SHAP explanations, abstention -> `UNATTRIBUTED`. Real benchmarks on open datasets with temporal and leave-one-entity-out splits.
2. **Learned guided tracing under free-API budgets** — a policy model prioritizes which branches to expand, reaching the exchange with fewer API calls than BFS. Headline metric: recall of true VASP exits vs API calls.
3. **Cash-out taxonomy for Indian reality** — VASP / P2P-OTC-suspected / private wallet / mixer / bridge / DEX swap / sanctioned. When funds leave the regulated perimeter, say so and recommend a different legal route instead of forcing an exchange guess.
4. **Multi-chain**: TRON (USDT-TRC20), Ethereum (+ERC-20), Bitcoin; Solana as stretch. Swap/bridge hop handling.
5. **Batch triage**: rank many complaints by expected recoverable value and time-to-cash-out.
6. **Auditability**: SHA-256 of every raw provider response, reproducibility manifest (model/label/config versions), append-only audit log.
7. **Fully free & offline-capable**: cached fixtures give deterministic demos with zero API dependency.

## Non-goals
Identifying real-world persons; sending legal requests; holding keys; claiming court admissibility; paid intel parity (Chainalysis/TRM). Say so in the UI and docs.

## Users
Cyber-crime investigator (case work), supervisor (triage, review), admin (labels, models, users).

## Success metrics (all auto-generated by `make eval`)
- M1 role classifier: macro-F1, per-class PR-AUC, ECE (calibration), leave-one-exchange-out generalization.
- M3 guided tracer: VASP-exit recall @ N API calls vs BFS / taint-weighted baselines.
- Pattern detectors: precision/recall on synthetic injected patterns (labeled SYNTHETIC).
- Time-to-attribution on demo cases; end-to-end latency in offline mode.
- Coverage: chains supported, label counts by source.
